## 1. 为什么这次评审不能靠目测

材料是给学生打印下发的，出错成本高但错误类型很隐蔽：

| 风险 | 目测能否发现 | 本次做法 |
|---|---|---|
| 选题卡里的类/关系数、示意语料抽取数与仓库实际不一致 | 不能（8 张卡 × 4 个数字） | 解析 `topics/*/ontology.json` 与 `data/extraction/*_rule.json` 逐卡比对 |
| 与已定稿 `作业方案.md` 的口径漂移（金标准条数、评分权重、热身分值、答辩形式） | 很难 | 从方案文档里正则抽取口径，与一页纸/HTML 交叉核对 |
| 改了 markdown 却忘了重新导 PDF（**本次真实踩到**） | 完全不能 | 比对 PDF 与源文件的 mtime，并用 pypdf 读回真实页数核对文中声明的页数 |
| 打印出来某页只有 1/3 内容、其余空白 | 要在 PDF 阅读器里逐页翻 | 渲染每页位图，量深色内容的首末行，算填充率 |
| 选题卡缺必要板块（参考文献/数据/代码入口） | 容易漏，尤其"缺一项"而非"写错" | 8 张卡逐块断言必需要素 |

新增两个可复现的检查器（已入库）：

```bash
cd network
.venv/bin/python tools/check_student_materials.py --verbose   # 六类一致性/完整性/时效性检查
.venv/bin/python tools/audit_pdf_layout.py                    # 逐页渲染量填充率
```

## 2. 发现与处置

### 2.1 必改（高）

**S1 · 8 个选题卡全部缺「参考文献」**

- 证据：`选题介绍.html` 原文每张卡的结构是「题目 ID → 一句话 → 本体图 → 三阶段 → 数据图 → 验收点 → 坑」，
  **没有参考文献板块**；而 `作业方案.md` 第 135 行明确写着"每个选题统一包含：… → 参考文献 → 风险与坑"，
  方案里八个选题各自也有 `**参考文献**：` 段落（第 175/217/256/295/334/375/412/450 行）。
  即：**方案里有、学生材料里丢了**——学生看不到参考资料，这是内容缺失而不只是排版问题。
- 处置：从方案逐题搬入并压缩（保持两文档同源，不另造文献），每卡加一行：

  ```html
  <p class="small"><b>参考文献</b>：…</p>
  ```

  8/8 已补。T7 顺手修正了一处标准号错配（见 S5）。

**S2 · 两份 PDF 都早于源文件（改了内容没重新导出）**

- 证据：`选题介绍.html` 在导出 PDF **之后**又被改过（补了页脚 PDF 链接），`学生作业说明.md` 亦同。
  mtime 比对：`学生作业说明.md` > `学生作业说明.pdf`，`选题介绍.html` > `选题介绍.pdf`。
  这类不一致最危险的地方是**看不出来**——PDF 打开仍然正常，只是内容是旧的。
- 处置：重新导出两份；并把 mtime 检查写进 `check_student_materials.py`，以后忘记重导会直接报「高」。

### 2.2 应改（中）

**S3 · T1 与 T7 的"数据集"只存在于 SVG 图里，没有可选中/可复制的文字**

- 证据：T1 的数据来源只画在 `<figure><svg>` 里（NetBox / Batfish / SNDlib / 设备配置样本），
  T7 只有"版权红线"段而无数据来源行。其余 6 题都有 `数据：…` 文字行。
  后果：打印后能看到图，但学生复制不了链接、助教检索不到关键词；`<svg>` 里的文字在 PDF 中也不可提取。
- 处置：两题各补一条文字数据行（T1 标注 NetBox ★21689 / Batfish ★1503 / SNDlib / 校内配置样本须脱敏，
  并保留"Internet Topology Zoo 本机不可达"的实测结论；T7 写明标准全文不入库、只放条款编号与自写示意语料
  `topics/t7-mlps-compliance/fixtures/mlps_clause_sample.txt`，并给 NIST SP 800-53 Rev.5 作公开对照）。

**S4 · 选题卡没有"代码入口"，示例代码只存在于全局脚手架说明里**

- 证据：作业要求"各阶段目标示例代码或参考开源代码"。原文每卡的第③栏只写"Skill 或 MCP 接入 Intellect Agent"，
  没有一处指向具体文件；学生要自己从 `network/README.md` 反推 `kgc/rule.py` 对应哪个阶段。
- 处置：每卡加一行代码入口，统一给出"该选题的配置目录 → 三阶段引擎文件 → 一键脚本"：

  ```
  topics/<id>/（本体种子·抽取模式·词表·示意语料）· kgc/ontology.py → kgc/rule.py〡kgc/model.py〡kgc/llm.py
  → kgc/fuse.py → kgc/kg.py → kgc/agent_app.py；一键 bash scripts/run_all.sh <id>
  ```

  T5 额外指向 `data/corpus/t5-protocol-rfc/`（5 篇真实 RFC）。

**S5 · 打印排版：分页策略把内容推走，出现半页空白；且方案里一处标准号与名称错配**

- 证据（排版）：打印 CSS 给 `.card` 和 `.grid2/.grid3` 都设了 `break-inside: avoid`。
  一张"整块不可拆"的卡片只要在当前页放不下，就整块跳到下一页，前一页留白。
  逐页渲染实测（深色内容填充率）：**16 页，平均 74.8%，其中 p2=51%、p6=56%、p13=50% 三页明显偏空**。
- 处置：`.card` 与 `.grid2/.grid3` 改为 `break-inside: auto`（单个 `.stage`、`figure`、`table` 仍不拆）。
  实测变为：**15 页，平均 80.0%，无任何页低于 60%**。一页纸维持 1 页（填充率 88.7%）。
  文中所有"15 页"的声明与导出结果一致（由检查器自动核对）。
- 证据（事实）：`作业方案.md` T7 参考文献原写 `GB/T 25058（安全设计技术要求，可选）`。
  GB/T 25058-2019 是《网络安全等级保护**实施指南**》，"安全设计技术要求"是 **GB/T 25070-2019**，号与名错配。
- 处置：方案与 HTML 同步改为 `GB/T 25058-2019（实施指南）、GB/T 25070-2019（安全设计技术要求，可选）`。

## 7. 追加：页码页眉（同日实施）

**需求**：两份 PDF 加页码页眉（课程名 + 材料名 + 第 x / y 页）。

**为什么不用 Chrome 自带页眉**：headless Chrome 的页眉页脚只有开关（`--no-pdf-header-footer`），
内容固定为标题/URL/日期，改不了；CSS Paged Media 的 `@page { @top-center { content: … } }`
页边距盒子 Chrome 不支持，`counter(page)` 因而也用不上。

**做法**：CSS 里把页眉/页脚所需的高度做成页边距，导出后用 PyMuPDF 往留白里叠印。

| 环节 | 处理 |
|---|---|
| 版心 | 一页纸 `margin:13mm 9mm 9mm`；图文版 `margin:15mm 9mm 12mm`（上 15mm 收页眉、下 12mm 收页码） |
| 页眉 | 左：`《知识图谱技术与应用》· 网络工程专业实践作业`；右：`{材料名} · 第 x / y 页`；下加 0.6pt 细线 |
| 封面 | 图文版第 1 页是深色 hero 区，页眉压上去看不清 → 该页不印页眉，改在页脚印 `选题介绍 · 8 选题图文详解` + `第 1 / 15 页`，页码不缺席 |
| 字体 | PyMuPDF 内置简体中文字体 `china-s`（免装字体），7.2pt，灰 #6b7280 —— 叠出来的文字**可选中、可检索** |

**为什么不会压到正文**：页眉基线取 `页眉带 − 13pt`，而正文由 CSS `@page` 强制从页眉带以下开始，
重叠在结构上不可能发生，不靠目测。

**验证（真实渲染 + 文字回读）**：

```
学生作业说明.pdf: 1 页 · 页码 1/1 完整 · 平均填充 88.6%
选题介绍.pdf:    15 页 · 页码 15/15 完整 · 平均填充 79.8% · 偏空页 无
```

- 逐页 `get_text()` 回读：15/15 页都含「第 k / 15 页」；叠印函数内置该校验，失败即 `sys.exit`。
- 位图量行带：页眉文字带与正文首行之间留 36px（scale 2.2）空隙，无重叠；页眉左右两簇文字中间
  仅 1 处空隙，说明左右对齐正常。
- 页数未变（15 页），文中「15 页」的声明无需改动；`check_student_materials.py` 新增
  `check_page_marks()`，以后页眉被去掉、或页数改了却没同步文案，都会直接报「高」。

**代价**：一页纸内容整体下移 4mm（填充率 88.7% → 88.6%，仍 1 页）；图文版平均填充 80.0% → 79.8%
（页数不变）。`--no-header` 可随时导出无页眉版本做对照。
