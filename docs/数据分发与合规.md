# 数据分发与合规边界（评估结论 + 操作规则）

> 评估日期：2026-10-14 · 适用仓库：`gitee.com/ontoweb/kgcase`（含 `power/`、`network/`）
> 触发背景：教务侧已决定**参考答案开放**（脚手架、示意语料、基线产物对学生可见），
> 因此必须明确"哪些能公开、哪些只能给链接、哪些必须脱敏或不入任何仓库"。

---

## 1. 结论（一句话）

**公开的是"方法与脚手架的产物"，不是"受约束的原始材料"。**
仓库可以公开：自写代码、自造示意语料、公开可再分发文本（RFC）、数据集**获取脚本与 ID**、基线评测结果；
不得公开：推荐性国家标准全文、实验室设备配置、自采日志、任何含真实凭据/内网拓扑的文件。

---

## 2. 逐类评估矩阵

| 类别 | 具体材料 | 可否入库公开 | 依据 | 正确处理方式 |
|---|---|---|---|---|
| 标准规范文本 | RFC 全文（T5） | ✅ **可以** | IETF Trust 法律条款允许完整复制与再分发，文件内已含版权声明 | 现状保持：`network/data/corpus/t5-protocol-rfc/rfc*.txt`（5 篇 ≈450 KB） |
| 国家标准 | GB/T 22239-2019、GB/T 28448-2019（T7） | ❌ **不可以** | 推荐性国家标准（GB/T）在标准委平台仅提供在线阅读，**无再分发授权**；文本内也有版权页 | 学生经校内正版渠道/图书馆获取；仓库只保留**条款编号与自写示意语料**（`mlps_clause_sample.txt` 即为此类），并在报告中注明来源 |
| 设备配置 | 实验室 Cisco/华为/Juniper 配置（T1/T8） | ❌ **不可以**（脱敏后仍建议不入公网） | 含管理地址、口令散列、内网拓扑与业务命名 | ① 用自造示意语料（`campus_network.txt`、`device_config_sample.txt`，使用 RFC 5737 文档用网段与虚构主机名）；② 真实配置只在**私有仓库**或校内环境使用，提交前 `enable secret/username ... password/snmp-server community` 全部替换 |
| 日志 | Loghub 等公开数据集（T3） | ⚠️ **只放链接与脚本** | Loghub 为研究用途授权（再分发须引用原仓库与论文） | `scripts/fetch_corpus.py` 提供下载入口；**不把数据集本体复制入库**（也是 83.4 GiB 级别的体量问题） |
| 日志 | 自采 syslog / 网络设备日志 | ❌ **不可以** | 含真实内网 IP、主机名、业务信息，可能触及保密要求 | 仅保留**≤100 行**脱敏样本并显式标注"已脱敏示意"；其余不入库 |
| 第三方数据集 | security-kg 三元组（T2）、CVE/ATT&CK STIX、CIC-IDS 等 | ⚠️ **只放脚本、ID、许可说明** | 汇总型数据集的上游许可差异大（ExploitDB GPLv2+、Sigma DRL 1.1、ENGAGE 非商用），**商用可依性取决于最严的那一环** | 报告列出逐源许可清单；仓库只放"取数脚本 + 数据集 ID + 许可表"；需要时取 1–2 个源切片 |
| 论文/规范 | arXiv 论文、OCP/UEC 规范（T6） | ⚠️ 放链接与摘要级引用 | 版权归原作者/组织 | 仓库只放链接与自写要点笔记 |
| 学生成果 | 各组 GitHub/Gitee 仓库 | 由学生自定 | 见 §4 学生须知 | 若含实验室数据 → 仓库必须私有；提交给教师时附合规声明 |
| 参考答案 | 脚手架、示意语料、T5 基线产物与文档 | ✅ **已决定开放** | 均为本仓库自造/可再分发内容，且不含受限材料 | 现状保持；配合"差异化要求 + 答辩追问代码"防止直接抄答案（见方案文档 §7） |

## 3. 机器化门禁（不靠"记得别提交"）

`tools/check_restricted_data.py` 在提交前扫描仓库或暂存区：

```bash
cd ~/workspace/kgcase/network
.venv/bin/python tools/check_restricted_data.py           # 全仓扫描（本次实测：154 个文本文件，0 问题）
.venv/bin/python tools/check_restricted_data.py --staged   # 只扫暂存区，适合 pre-commit
```

**判据（分级）**

| 级别 | 判据 |
|---|---|
| 高 | 疑似标准全文（含 `GB/T 22239/28448` 且章节编号行 ≥20 且 >30 KB）；疑似设备配置（≥5 行厂商配置特征）；疑似真实凭据（`password/secret/api_key/token = <非占位符>`）；二进制/归档（`.pcap/.parquet/.zip/.pem/.key/...`） |
| 中 | >5 MB 的大文本文件（原始数据集应改为下载脚本） |
| 低 | `.txt/.log/.csv` 中 ≥6 行 syslog 时间戳；配置类文件里处于 `ip/address/gateway/neighbor/peer` 或 `/掩码` 上下文中的非文档用网段地址 |

**白名单（按 sha256 内容指纹判定，不按路径——路径白名单可被绕过）**
- `topics/*/fixtures/*.txt` 及其内容相同的 `data/corpus/<topic>/` 副本：自写示意语料；
- `data/corpus/t5-protocol-rfc/rfc*.txt`：RFC 全文（可再分发）；
- 占位符凭据（`***`、`<...>`、`${ENV}`、`changeme`）不计为凭据。

**退出码非 0 表示存在高风险项，不得提交。** 建议接入 pre-commit：

```bash
# .git/hooks/pre-commit
.venv/bin/python network/tools/check_restricted_data.py --staged --quiet || {
  echo "存在受限内容，提交已阻止"; exit 1; }
```

`.gitignore` 已按类别忽略：`restricted/`、`device-configs/`、`lab-logs/`、`*.pcap*`、`*.parquet`、`*.pem`、`*.key`、`.env`。

## 4. 学生须知（随作业下发的三条规则）

1. **只用两类数据**：① 公开可下载且许可明确；② 自造/脱敏样本（≤100 行，标注"示意"）。
2. **标准全文、设备配置、自采日志不上传任何公开仓库**——包括个人 GitHub/Gitee；需要时放在私有仓库，或在报告中只引条款号与结论。
3. **提交时附"数据来源与合规声明"**（下方模板），教师按声明抽查。

### 数据来源与合规声明（模板）

| 数据集/材料 | 来源 URL | 版本/下载日期 | 许可 | 是否含真实环境信息 | 脱敏方式 |
|---|---|---|---|---|---|
| 例：RFC 9293 | https://www.rfc-editor.org/rfc/rfc9293.txt | 2026-10-14 | IETF Trust（可再分发） | 否 | — |
| 例：实验室接入交换机配置 | 校内导出 | 2026-10-16 | 内部 | 是 | 替换主机名/管理地址/口令，仅保留接口与网段结构 |
| 例：GB/T 22239-2019 | 校内正版渠道 | — | 仅阅读，不再分发 | 否 | 仅引用条款编号 |
