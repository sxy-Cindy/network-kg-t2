# 《知识图谱技术与应用》实践作业说明（学生版 · 一页纸）

> 网络工程专业 · **16 学时（4 周 × 4 学时）** · 2–3 人/组 · 线下自行分组 · 提交到**本组自己的 GitHub/Gitee 仓库**

## 一、你要做的三件事（每个选题都一样）

| 阶段 | 做什么 | 交出什么 | 关键要求 |
|---|---|---|---|
| **① 本体构建** | 从标准/规范/语料里设计类、关系、属性 | `ontology.ttl`（OWL）+ `ontology.json` | 类 ≥10、关系 ≥10，每项注明来源；本体自检 0 问题 |
| **② 三种方法建图谱** | 用**规则/词典**、**机器学习模型**、**LLM** 三条路线抽同一份语料，再融合 | 三份抽取结果 + 融合结果 + 图谱（JSON/TTL/GraphML） | 每条关系带**原文证据**；对金标准报 P/R/F1；质量门槛：垃圾实体 0、域值域违规列出 |
| **③ 基于 KG 的 Agent 应用** | 把图谱接入 Intellect Agent（Skill 或 MCP），做可溯源问答 | ≥8 题问答集 + 幻觉率 + 溯源链 | **没有验证的生成不算 KG 增强**：逐句核对答案是否有三元组支撑 |

**贯穿主线（答辩必问）**：三种方法**各自擅长抽哪类知识？代价是什么？** —— 用你自己实测的数字回答。

## 四、评分与答辩

**总分 100**（另：公共热身 5 分作准入权重；加分项累计 ≤10 分）：本体质量 15 · 数据与合规 10 · 方法A 8 · 方法B 12 · 方法C 12 · 融合与质量 10 · 阶段三应用 15 · 报告与可复现 8 · **答辩 10**。
加分项（可选）：金标准标注工作坊 5 · 脚手架改进 5 · 多跳问答扩展 5。

**答辩 = 现场演示系统 + 讲解代码 + 回答针对代码的提问**（不做 PPT 汇报）。流程：演示跑通一条命令（2 分钟）→ 自选 1 个模块讲清数据流与取舍（3 分钟）→ 就代码提问（3–5 分钟）。提问示例："`max_gap` 改成 0 或 100 会怎样？"、"方法B 的 F1 只有 0.044，是模型问题还是标注问题？给你的证据。"

## 五、三条数据红线（会被门禁脚本拦住）

1. **只用两类数据**：公开可下载且许可明确；或自造/脱敏样本（≤100 行并标注"示意"）。
2. **不上传**推荐性国家标准全文（GB/T 系列）、实验室设备配置、自采日志到任何公开仓库（含个人仓库）；需要时仅放私有仓库，报告里只引条款号与结论。
3. **提交时附"数据来源与合规声明"**（数据集/来源/版本/许可/是否含真实环境信息/脱敏方式）。提交前自检：
   `.venv/bin/python tools/check_restricted_data.py`

## 六、开始动手（10 分钟跑通）

```bash
cd network
python3.11 -m venv .venv && .venv/bin/pip install -r requirements.txt   # 或用阿里云镜像
bash scripts/run_all.sh t5-protocol-rfc          # 一键跑通三阶段（T5 公共热身）
.venv/bin/python -m kgc.agent_app --topic t5-protocol-rfc bench   # 问答可回答率 + 幻觉率
.venv/bin/python scripts/mcp_smoke_client.py --topic t5-protocol-rfc  # MCP 链路自检
# 换成自己的选题：先跑离线示意语料
bash scripts/run_all.sh <你的选题 id> --fixture
```

**改什么**：`topics/<你的选题>/` 下 `ontology.json`（本体）、`patterns.yaml`（规则）、`lexicons.yaml`（词典）、`gold.jsonl`（金标准）；**不用改** `kgc/` 引擎代码。

## 七、最容易失分的 5 件事

1. **金标准写错**：写进语料里根本不存在的条目 → 所有方法的召回被无理由压低（先跑 `scripts/check_gold.py`）。
2. **规则法写太宽**：抽出上百条噪声边却只看召回 → 必须看 precision（金标准是抽样，precision 是**下界**）并做人工抽检。
3. **阶段三没有验证环节**：让 LLM 自由回答、不回扣三元组 → 直接扣分项。
4. **指标口径不写清**：金标准规模、实体归一化口径、阈值（`max_gap`/`min_prob`/Top-k）不写 → 跨组数字不可比。
5. **只报成功不报失败**：负面结果与踩坑必须写进报告（本课程看重"如实"）。
